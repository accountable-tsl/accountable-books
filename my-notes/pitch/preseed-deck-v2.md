## 3. The Problem

Accounting firms scale on headcount, not systems.

- Month-end close is a coordination problem: missing docs, stale feeds, uncategorized items
- Firms lack a single “what to do next” queue across all client books
- Existing stacks are stitched together: GL + PM tool + spreadsheets + chasing clients

**Visual:** “month-end chaos” map (client questions -> accountant work -> delays).

---

## 4. The Insight (What’s Different)

Accounting software shouldn’t start with reports. It should start with **what needs doing**.

- **Action clarity:** clients see required actions; bookkeepers see the next queue item
- **Drillable truth:** every number traces to the source evidence
- **Safe AI:** AI suggests and explains; posting requires explicit confirmation

**Visual:** “Action Center + Readiness Center” mock/wire (even simple boxes works).

---

## 5. The Wedge (What We Do)

Turn bank activity into **a review queue that closes the month**.

- Ingest: Plaid (US) + Mono (NG) + CSV
- Classify: rules + ML with **reasons**; exceptions routed to a human queue
- Post: double-entry ledger; accounting edits are versioned (audit-safe)

**Visual:** pipeline diagram (Ingest -> Suggest -> Review -> Post).
